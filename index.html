⚡ Key insight — glibc 2.39
tcache (added in 2.26) holds up to 7 chunks per size class in a singly-linked LIFO list, and is checked before any lock is taken. Since 2.32 the next pointer is mangled by PROTECT_PTR (safe-linking), and since 2.29 each entry also carries a key for double-free detection — so a freed tcache chunk holds two words, not one. malloc() adds only 8 bytes of overhead, not 16: the next chunk's prev_size is borrowed while this chunk is in use.

What this model simplifies
One arena, one thread, no locking shown. Sizes, bin ranges, search order, splitting and coalescing are faithful to 2.39. Not modelled: the binmap scan of larger bins, malloc_consolidate() on large frees, last_remainder, mmap() for requests ≥ 128 KB, and the corruption checks in _int_free.
